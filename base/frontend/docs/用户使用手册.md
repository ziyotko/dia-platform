## 一、系统概述

Base 底座是「管理后台底座」：它自己不含业务功能，而是把已有的业务系统（门户、会员、应用等）作为**子应用**统一接入，负责统一登录、租户、应用、用户/角色/权限、菜单、消息、审计与审批。

### 1.1 访问方式

| 项 | 值 |
| --- | --- |
| 正式地址 | `http://<域名>/business_base/`（由 Nginx 托管） |
| 本地开发 | `http://localhost:3000/business_base/`（`npm run dev`） |
| 登录页 | `http://<域名>/business_base/login` |
| 后端 API 前缀 | `/business_base/api`（前端已自动拼接，无需手工输入） |

> 部署子路径与接口前缀由前端 `.env`（`VITE_BASE_PATH` / `VITE_API_BASE_URL`）与后端 `config.yaml` 的 `server.api_prefix` 共同决定；若运维改了子路径，访问地址会随之变化（如 `/xxxxx/`）。

### 1.2 浏览器要求

- Chrome / Edge 等 Chromium 内核浏览器（推荐最新版）；Firefox / Safari 基本可用。
- 需允许浏览器 Cookie 与本地存储（`localStorage` 保存登录 Token）。
- 分辨率建议 ≥ 1440×900；界面按 100% 缩放查看（侧边栏为图标 + 悬浮菜单布局）。

### 1.3 核心概念

| 概念 | 说明 |
| --- | --- |
| 租户（Tenant） | 平台中的组织单位，用户、角色、应用实例、流程角色等均归属租户 |
| 平台级（`tenant_id = 0`） | 属于平台而非某个租户的数据：平台超管、预置菜单、系统设置、应用定义、接口权限点 |
| 应用（App） | 一个可被接入的子系统：名称、编码（`appCode`）、前端入口、后端入口、接入方式（IFrame / API 代理） |
| 应用实例（AppInstance） | 应用在租户下的开通实例（同一租户 + 同一应用只能开通一次） |
| 用户 / 角色 / 菜单 / 权限 | 角色绑定菜单（决定页面可见）与接口权限点（决定接口可调用）；用户通过角色获得能力 |
| 机构（Organization） | 树形组织结构，用户可指定所属机构 |
| 流程角色（WorkflowRole） | 审批职责的集合（如审核组/复审组），**只决定「谁能审批」**，与决定菜单/接口的系统角色无关 |
| 流程定义 / 流程实例 / 审批任务 | 一条审批链路 / 一次具体审批 / 落在某审批人身上的待办 |
| 超管与租户管理员 | **平台超管**（`tenantId = 0`）跨租户并管理平台级资源；**租户管理员**（用户表单勾选「管理员」）在本租户内拥有全部菜单与接口权限 |

## 二、登录与账号

### 2.1 登录页

页面标题为「Base 管理后台」，副标题「统一的企业级管理底座」，居中卡片包含：

| 字段 | 说明 |
| --- | --- |
| 租户编码 | **平台管理员可留空**；租户用户必须填写自己的租户编码（登录按「租户编码 + 用户名」定位） |
| 用户名 | 必填 |
| 密码 | 必填，可点击眼睛图标查看明文 |
| 验证码 | **仅当「系统设置 → 安全策略 → 登录验证码」开启时出现**；5 位数字+字母，点击图片可刷新 |

登录页会在加载时调用公开接口 `GET /site-info` 判断是否显示验证码；该接口不可用时**默认显示**验证码（保守策略）。

### 2.2 登录步骤

1. 打开 `http://<域名>/business_base/`，未登录会自动跳转到登录页。
2. （租户用户）填写租户编码；输入用户名、密码。
3. 若显示验证码：照图输入（不区分大小写），看不清就点击图片刷新。
4. 点击「立即登录」（也可在任意输入框按回车）。
5. 登录成功后进入系统并跳转到第一个有权限的菜单（通常是「控制台」）。

**登录失败的可能原因**

| 提示 | 原因 / 处理 |
| --- | --- |
| 用户名或密码错误 | 核对账号；验证码错误也计入失败次数 |
| 账号已被锁定，请稍后再试 | 连续失败达到「最大失败次数」（默认 5 次）会锁定「锁定时长」（默认 30 分钟），可等待或由管理员调整安全策略 |
| 请求过于频繁，请稍后再试 | 触发登录接口限流（默认 10 次/分钟），稍后重试 |
| 验证码已过期，请刷新后重试 | 验证码 Redis TTL 为 5 分钟且一次性，刷新页面或点击图片重新获取 |

### 2.3 内置账号与角色

| 账号 | 密码 | 角色 | 说明 |
| --- | --- | --- | --- |
| `admin` | `admin123` | 超级管理员（`tenant_id = 0`, `code = super_admin`） | 首次启动自动创建；**上线后请立即在「个人中心」修改密码** |

租户内的第一个管理员由平台超管创建（见 5.4 用户管理），创建时勾选「管理员」。

### 2.4 忘记密码

系统**没有**自助找回密码入口。请联系平台超管或租户管理员在「系统管理 → 用户管理 → 重置密码」中设置新密码；自己修改密码请到「个人中心 → 修改密码」。

> 修改密码或管理员重置密码后，该账号**此前签发的所有 Token 立即失效**（其它设备会被强制退出登录）。

### 2.4 登录有效期与自动续期

- 登录后浏览器本地会保存一枚 **access token**（默认 8 小时）与一枚 **refresh token**（默认 7 天）。
- access token 快到期时，页面会自动用 refresh token 换一枚新的（**每次续期旧 refresh token 立即作废**），所以只要你在 7 天内打开过系统，就不用反复登录。
- 连续 7 天以上未使用、退出登录、被管理员**禁用/删除账号**、修改或重置密码，都会让会话立即失效，需重新登录。
- 安全提示：不要把浏览器里的登录状态随意导出或分享；若怀疑凭证泄露，请修改密码（会让全部会话失效）。

## 三、主界面与通用操作

### 3.1 左侧图标栏与悬浮菜单

- 左侧固定 64px **图标栏**：顶部是平台 Logo 方块，下面是顶级菜单图标（鼠标悬停显示菜单名）。
- 鼠标悬停图标约 0.12 秒后，右侧**弹出 220px 的二级菜单面板**；移开约 0.18 秒自动收起，切换路由也会收起。
- 若某个顶级菜单**没有子菜单**（如「控制台」），点击图标直接进入该页面。
- 侧边栏**没有折叠/展开按钮**，这是设计如此。

### 3.2 顶栏

| 区域 | 内容 |
| --- | --- |
| 左侧 | 面包屑（分隔符 `/`，可点击上级跳转；无匹配时显示「首页」） |
| 右侧 | 消息铃铛（带未读数角标）、用户头像下拉 |

**消息铃铛**

- 「消息中心」→ 跳转「消息管理 → 消息列表」。
- 「全部标为已读」：未读为 0 时提示「没有未读消息」；否则二次确认后批量标记，成功提示「已标记 N 条为已读」。
- 未读数每 30 秒自动刷新一次；在消息页做读操作后会立即刷新。

**用户下拉**：个人中心 / 修改密码（均进入个人中心页）/ 退出登录。

> 「退出登录」会调用后端登出接口把当前 Token 加入黑名单，再清理本地会话。

### 3.3 内容区

- 页面以白色卡片承载：卡片头左侧是标题，右侧是操作按钮；下方依次是查询区、表格、分页。
- 若当前账号**没有分配任何菜单**，内容区顶部会出现常驻告警条：
  「当前账号未分配任何菜单权限」+「请联系管理员在「系统管理 → 角色管理」中为该账号分配角色与菜单后再使用。」
  此时会被固定落在「个人中心」页。

### 3.4 通用交互习惯

- 列表页统一：`查询 / 重置`（查询与重置都会把页码重置为第 1 页）、分页固定每页 10 条（无每页条数选择、无列排序）。
- 关键字输入框支持**回车即查询**。
- 删除、撤销、发送等敏感操作都会先弹出确认框；成功后右下角出现绿色提示。
- 表格操作列固定在右侧，按钮为文字链样式。
- 权限控制：没有权限的按钮**不显示**（而非置灰）；平台级资源（应用管理、权限管理、系统设置）对非平台超管整体只读或不可见。
- 「页面缓存」：菜单若勾选了「页面缓存」，切换页签再回来时不会重新加载（保留筛选条件与页内状态）。

## 四、控制台（工作台）

进入系统后的默认首页，按**账号可见范围**分三档展示，不同角色看到的卡片数量不同：

| 角色 | 资源概览 | 我的待办 | 趋势图 |
| --- | --- | --- | --- |
| 平台超管（`tenantId = 0`） | 13 张卡片（含「租户数」「启用租户」） | 3 张 | 3 张 |
| 租户管理员（勾选「管理员」） | 11 张卡片（无租户数/启用租户，「应用数」变为**已开通应用**） | 3 张 | 3 张 |
| 普通用户 | **不显示**（保持 0） | 3 张 | **不显示** |

### 4.1 资源概览卡片

租户数、启用租户（仅超管）、应用数（超管）/ 已开通应用（租户管理员）、应用实例、用户数、启用用户、管理员、角色数、机构数、消息数、今日新增用户、今日登录、今日登录失败。

### 4.2 「我的待办」卡片（整卡可点击）

| 卡片 | 数值来源 | 点击跳转 |
| --- | --- | --- |
| 未读消息 | 当前用户未读数 | 消息管理 → 消息列表 |
| 待我审批 | 当前用户待处理任务数 | 工作流管理 → 我的待办 |
| 审批中的流程 | 管理员=本租户/全平台审批中实例数；普通用户=我发起的进行中流程数 | 工作流管理 → 流程实例 |

### 4.3 趋势（近 7 天）

三张零依赖柱状图卡片：新增用户 / 登录次数 / 新增消息。每根柱子上方为当日数量、下方为 `MM/DD`；卡片头右侧显示「近 7 天合计 N」。无数据的日期按 0 处理。

### 4.4 平台能力（固定说明卡片）

多租户管理、应用接入（IFrame 嵌入或 API 代理）、权限控制（角色 + 菜单细粒度）、组织架构（多级机构与人员）、消息中心（模板与通知）、系统配置（字典/参数/审计）——纯说明，无数据。

### 4.5 我的应用

若当前租户已开通应用，会展示「我的应用」卡片：每项显示应用名与入口（API 前缀或前端地址），点击在新窗口打开。打开时底座会现场签发一个 **一次性接入票据**（`base_ticket`，60 秒有效、只能用一次）拼在地址后面，子应用用它换回会话与用户信息——不再把长期 Token 直接放进地址栏。

> 应用未配置前端入口时会提示「该应用未配置前端入口，请通过左侧菜单访问」。

## 五、系统管理

### 5.1 租户管理

**用途**：维护平台内的租户（组织单位）。**仅平台超管可见**，页面上也没有按钮级权限（本身就是超管专属）。

- 查询：关键字（租户名称 / 编码）。
- 列表：租户编码、租户名称、联系人、联系电话、状态（启用/禁用）。
- 新增/编辑（弹窗）：租户编码（必填，**编辑时不可修改**）、租户名称（必填）、联系人、联系电话、状态开关、描述。
- 删除：「确认删除该租户？」；若该租户下仍有用户 / 角色 / 应用实例 / 流程角色 / 流程定义 / 流程实例，会被**拒绝**并提示具体数量，需先处理下级数据。

> 删除是物理删除（不可恢复）。删除后可用同编码重新创建，但会是一条**全新记录（ID 不同）**。

### 5.2 应用管理

**用途**：注册可被接入的子应用。**新增/编辑/删除仅平台超管可用**（租户用户只能查看列表，用于了解可开通哪些应用）。

- 查询：关键字（应用名称 / 编码）。
- 列表：应用编码、应用名称、接入方式（`IFrame` / `API代理`）、前端入口、后端入口、状态。
- 弹窗字段：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 应用编码 | 是 | 唯一编码，如 `caam-portal`；**编辑时不可修改** |
| 应用名称 | 是 | - |
| 接入方式 | 是 | `IFrame`：子应用前端以 iframe 嵌入；`API代理`：子应用后端由底座反向代理 |
| 前端入口 | - | iframe 用地址，如 `http://localhost:5173` |
| 后端入口 | - | 代理目标，如 `http://127.0.0.1:8080` |
| API前缀 | - | 代理转发时拼在业务路径前（如 `/api`，留空直接转发） |
| 状态 / 排序 / 描述 | - | - |

- 删除：「确认删除该应用？」；该应用被租户开通（存在应用实例）时会被拒绝。

### 5.3 应用实例

**用途**：为租户开通应用，控制「哪些租户能用哪些应用」。

- 查询：**仅平台超管**可见「所属租户」下拉（可清空表示全部租户）。
- 列表：ID、应用名称、应用编码、所属租户、状态、配置。
- 「开通应用」（新增）：所属租户（**仅超管**，编辑时不可改）、应用（下拉，**编辑时不可改**）、状态开关、配置（JSON，多行文本）。
- 规则：**同一租户 + 同一应用不可重复开通**；删除后可以重新开通。
- 删除：「确认删除该应用实例？」

> 应用实例是子应用 API 代理的准入条件：未开通该应用的租户，调用 `/app/{appCode}/...` 会返回 403。

### 5.4 用户管理

**用途**：维护账号、所属机构、角色与初始密码。

- 查询：关键字（用户名 / 姓名 / 手机号）；**仅超管**可见「所属租户」下拉。
- 列表：用户名、真实姓名、手机号、邮箱、所属机构、所属租户（仅超管）、角色（多个用「、」连接）、状态、操作。

| 操作 | 说明 |
| --- | --- |
| 新增用户 | 填写下表字段；密码为**初始密码**，必须满足「安全策略 → 密码最小长度」（默认 8 位） |
| 编辑 | **用户名与所属租户不可修改** |
| 分配角色 | 弹窗提示「仅可选择同租户的角色」，多选后保存 |
| 重置密码 | 弹出密码输入框，输入新密码（同样受最小长度约束），确认后该用户旧 Token 立即失效 |
| 删除 | 「确认删除该用户？」；不能删除当前登录用户；不能删除平台内置 `admin` |

用户表单字段：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 所属租户 | 仅超管 | 编辑时不可改 |
| 用户名 | 是 | 编辑时不可改；**同一租户内不可重名，跨租户可同名** |
| 真实姓名 / 手机号 | - | - |
| 邮箱 | - | 填写时会做格式校验 |
| 所属机构 | - | 机构树选择，「不选表示未分配」 |
| 密码 | 仅新增 | 初始密码 |
| 管理员 | - | 「开启后在本租户内拥有全部接口权限与菜单」 |
| 状态 | - | 启用 / 禁用 |

> 禁用用户后该账号不能登录；已停用用户仍会保留在流程角色成员里，但不再适合承担审批（详见 7.1）。

### 5.5 机构管理

**用途**：维护树形组织结构，供用户归属选择。

- 无查询区，直接以树表展示全部机构（默认展开）。
- 列：机构名称、机构编码、负责人、联系电话、邮箱、状态、操作。
- 弹窗字段：上级机构（树选择，可清空表示根机构）、机构编码（必填）、机构名称（必填）、负责人、联系电话、邮箱、排序、状态、描述。
- 删除：「确认删除该机构？」；**存在子机构或仍有用户归属时会被拒绝**。

### 5.6 角色管理

**用途**：系统角色（决定「能看哪些菜单 + 能调哪些接口」）。

- 查询：关键字（角色名称 / 编码）；**仅超管**可见「所属租户」下拉。
- 列表：角色编码、角色名称、所属租户（仅超管）、备注、状态、操作。
- 弹窗字段：所属租户（仅超管，编辑时不可改）、角色编码（留空自动生成，编辑时不可改）、角色名称（必填）、状态、备注。
- **分配菜单**：树形勾选，弹窗提示「决定菜单（页面）的可见性；接口访问权限请在「分配权限」中设置」。回显只勾选**末级节点**（避免父节点连带的子节点被全部勾上），保存后用户重新登录或刷新即可看到菜单。
- **分配权限**：树形勾选接口权限点，标题为「分配接口权限」，提示「决定可以调用哪些接口；未分配任何权限的普通用户仅能浏览（GET）」。
- 删除：「确认删除该角色？」；**平台内置超级管理员角色（`super_admin`）不可删除**（按钮不显示）；删除角色会同时清理该角色与菜单/权限/用户的关联。

> 新租户用户看不到菜单的典型原因：其角色**没有分配菜单**。此时系统会提示「当前账号未分配菜单权限，请联系管理员」并落到个人中心页。

### 5.7 菜单管理

**用途**：维护底座与各子应用的菜单树（**菜单即路由**，没有菜单就没有页面）。

- 无查询区，树表展示：菜单名称、路由路径、组件路径、类型（目录/菜单/按钮）、应用编码、排序、操作。
- 弹窗字段：

| 字段 | 说明 |
| --- | --- |
| 所属应用 | 必填，`base` 或子应用编码 |
| 上级菜单 | 树选择，可清空表示根目录 |
| 菜单名称 | 必填（同时用于页面缓存识别） |
| 菜单类型 | 目录（`directory`）/ 菜单（`menu`）/ 按钮（`button`） |
| 图标 | Element Plus 图标名 |
| 路由路径 | 如 `/system/user` |
| 组件路径 | 如 `base/user/index.vue`；**iframe 菜单填外部地址** |
| 权限标识 | 如 `base:user:list`（保留字段） |
| 打开方式 | 当前页（`_self`）/ IFrame（`iframe`） |
| 排序 / 隐藏 / 状态 | - |
| 页面缓存 | 仅「菜单」类型且非 IFrame 时出现；开启后切换页签不重新加载该页 |

- 删除：「确认删除该菜单？」；存在子菜单时被拒绝。

### 5.8 权限管理

**用途**：维护接口权限点（全局基线）。**新增/编辑/删除仅平台超管可用**。

- 查询：应用编码（默认 `base`）。
- 页面提示：「接口权限点用于控制「哪些接口可以被调用」；在「角色管理 → 分配权限」中把权限授予角色。」
- 列表：权限名称、权限编码、类型（分组/接口/按钮）、方法、接口路径、状态、操作。
- 弹窗字段：应用编码（必填，`base` 或子应用编码）、上级权限（树选择）、权限名称（必填）、权限编码（必填，如 `base:user:create`）、类型（分组 / 接口 / 按钮）、**仅「接口」类型**才显示请求方法（GET/POST/PUT/DELETE）与接口路径（相对路径，如 `/users/:id`）。
- 删除有子权限时会提示「该权限下存在子权限，删除后子权限将失去归属，确认删除？」。

> **给子应用登记权限**：应用编码填子应用 `appCode`，路径填转发到子应用的业务路径。该应用一旦登记了权限点，未授权用户访问会被底座拦下（403）；一个都没登记则完全交给子应用自行鉴权。

### 5.9 审计日志

**用途**：记录所有登录后接口的调用（含请求参数与响应结果）。

- 查询：用户名、模块、方法（GET/POST/PUT/DELETE）、状态（成功=1 / 失败=0）、操作时间范围（精确到秒）。
- 列表：ID、用户名、模块、操作、方法、路径、IP、状态、耗时(ms)、操作时间、详情。
- 工具栏：批量删除（未选中时禁用）、清理、导出。
  - **清理**：弹出框要求输入保留天数（正整数，默认 30），早于该日期的日志会被清理。
  - **导出**：按当前筛选条件导出 CSV（文件名 `operation_logs_<时间戳>.csv`，带 UTF-8 BOM，Excel 打开中文不乱码）。
- 详情弹窗：用户名、模块、操作、方法、路径、IP、请求参数、响应结果（JSON 自动美化，最多 200px 高度可滚动）。

> **安全约定**：修改密码、重置密码、保存系统设置这三类请求的**请求体不落库**（显示为 `[敏感参数已脱敏]`）；请求体/响应体超过 4KB 会截断。

### 5.10 登录日志

- 查询：用户名、状态（成功/失败）、登录时间范围。
- 列表：ID、用户名、IP、UserAgent、状态、消息、登录时间（无行内操作）。
- 工具栏：批量删除、清理（保留天数）、导出 CSV（`login_logs_<时间戳>.csv`）。

> 登录失败也会记录（用户不存在时 `user_id` 为 0），可用于排查暴力破解。

### 5.11 数据字典

**用途**：维护下拉/枚举类数据的统一来源。

- 查询：字典编码、字典名称。
- 列表：ID、字典编码、字典名称、描述、状态、操作。
- 字典弹窗：字典编码（必填，编辑时不可改）、字典名称（必填）、描述、状态。
- **字典项管理**（700px 弹窗）：行内编辑「显示名 / 字典值 / 排序」，可「新增项」或删除行，最后点「保存」**整体覆盖**提交。

### 5.12 文件管理

- 无查询区；列表：ID、文件名、类型、大小（自动 B/KB/MB/GB）、存储、上传时间、操作。
- 「上传文件」支持扩展名：`.jpg .jpeg .png .gif .pdf .doc .docx .xls .xlsx .ppt .pptx .txt .zip .rar .mp4`；
  单文件大小上限由后端 `server.max_upload_mb` 控制（默认 **50MB**）。
- 「预览」：图片类型直接内嵌显示，其它类型提示「暂不支持该文件类型预览，请下载查看」，可点「下载」保存。
- 「删除」：「确认删除该文件？」（同时删除磁盘文件；删除后原访问地址失效）。

### 5.13 系统设置

**平台级配置，仅平台超管可查看与修改**；非超管进入该页会看到提示「系统设置为平台级配置，仅平台超级管理员可查看与修改」，且不会请求接口。

4 个页签：

#### （1）基础配置

| 字段 | 说明 |
| --- | --- |
| 平台名称 | 默认「Base 底座平台」；会显示在登录页标题与浏览器标签标题（页签）上 |

## 七、工作流管理

底座内置一条简单可预测的审批引擎：**节点按顺序串行审批**，同一节点内支持或签/会签。

### 7.1 流程角色

**用途**：定义「谁能审批」——与系统角色（决定菜单与接口权限）**互相独立**。

- 页面提示：「流程角色用于给审批流程的节点指定「谁有资格审批」，与系统角色（决定菜单与接口权限）互相独立」。
- 查询：关键字（角色名称 / 编码）、状态（启用/禁用）；仅超管可见「所属租户」。
- 列表：角色编码、角色名称、所属租户（仅超管）、**成员数**（0 人时显示橙色标签）、角色说明、状态、操作。
- 角色弹窗：所属租户（仅超管，编辑时不可改）、角色编码（留空自动生成，编辑时不可改，租户内唯一）、角色名称（必填，如「审核组 / 复审组」）、状态、角色说明。
- **成员配置**：多选用户（支持按用户名/姓名搜索）；**停用用户不可选**，若已在成员中会标注「- 已停用」；底部提示「已选 N 人；停用用户不可选，如需使用请先在「用户管理」中启用」。
- 删除：`确认删除流程角色「{名称}」？`

> ⚠️ 角色**无成员**时，引用该角色的审批节点会**自动通过**（并写一条「自动通过」流转记录），因此创建流程前请先配好成员。

### 7.2 流程定义

**用途**：定义审批链路并编排节点。

- 页面提示：「节点按顺序串行审批；同一节点内默认「或签」（任一人处理即通过该节点），可改为「会签」（全部通过才通过）；节点无有效审批人时自动通过」。
- 查询：关键字（流程名称 / 编码）、状态（启用/停用）；仅超管可见「所属租户」。
- 列表：「审批节点」列以标签展示节点顺序与名称（未配置时灰字「未配置节点」）、状态（启用 / 停用）。
- 流程弹窗：所属租户（仅超管，编辑时不可改）、流程编码（如 `content-audit`，租户内唯一）、流程名称（如「内容审核流程」）、状态（停用后不能发起新实例，已发起的不受影响）、流程说明。

**节点编排**（点击「节点编排」打开 900px 弹窗）：

| 列 | 说明 |
| --- | --- |
| 顺序 | 「上移 / 下移」调整串行顺序（首行不可上移、末行不可下移） |
| 节点名称 | 如「初审」 |
| 审批人类型 | 流程角色 / 指定用户 / 发起人本人（切换类型会清空已选审批人） |
| 审批人 | 选流程角色或用户（已停用会标注）；类型为「发起人本人」时显示灰字 |
| 审批方式 | 或签（默认）/ 会签 |
| 超时提醒(分钟) | 0 表示不提醒，最大 10080（7 天） |
| 节点说明 | 可选 |
| 操作 | 删除该节点 |

弹窗底部提示（原文）：「流程角色需先在「流程角色」中配置成员；角色无成员时该节点会自动通过；「或签」= 任一审批人处理即通过该节点，「会签」= 全部审批人都通过才通过（任一驳回即流程驳回）；超时提醒 0 表示不提醒，待办超过该时长未处理会向审批人发站内信催办」。

保存前校验：每个节点必须有名称；除「发起人本人」外必须选择审批人或流程角色。
**若该流程存在「审批中」的实例，节点保存会被拒绝**（避免流程跑到一半结构变了）。

### 7.3 流程实例

**用途**：发起流程、查看进度与流转记录、撤销。

- 查询：关键字（标题 / 流程名称）、流程、状态（审批中/已通过/已驳回/已撤销）；管理员额外有「只看我发起的」勾选框；仅超管可见「所属租户」。
- 列表：标题、流程、所属租户（仅超管）、发起人、当前节点、状态标签、发起时间、操作。
- 操作：详情（抽屉）、撤销（仅**审批中**且「我是发起人或我是管理员」时显示）、删除（需「删除流程实例」权限，仅管理员）。

**发起流程**弹窗：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 流程 | 是 | 只列出**启用中**的流程，并显示「N 个节点」；若所选流程没有节点会提示「该流程尚未配置审批节点，无法发起」 |
| 标题 | 是 | 如「2026 年度报告发布申请」 |
| 业务类型 / 业务ID | - | 可选，用于关联业务单据（如 `article`） |
| 申请说明 | - | 可选 |

提交成功提示「已提交，等待审批」。

**流程详情抽屉（640px）**：

- 顶部信息：流程、状态、发起人、发起时间、当前节点、结束时间、业务类型/业务ID（有值才显示）、申请说明。
- 「审批任务」表：节点（会签节点带「会签」标签）、审批人、结果（被催办过的任务带红色「催」标签，悬停显示「已催办 N 次，最近 <时间>」）、意见、处理时间。
- 「流转记录」时间线：显示动作（发起流程 / 审批通过 / 审批驳回 / 撤销流程 / 自动通过 / 流程完成 / 转办 / 加签 / 超时提醒）、操作人、（节点名）与意见。

**撤销**：`确认撤销「{标题}」？撤销后流程立即终止。`

### 7.4 我的待办

两个页签：**「待我审批」** / **「我已处理」**；右上角「刷新」按钮。

- 列表：标题、流程、审批节点（会签节点带「会签」标签）、发起人、提交时间、「处理结果」（仅「我已处理」页签显示）、流程状态、操作。
- 「待我审批」行操作：

| 操作 | 说明 |
| --- | --- |
| 详情 | 打开流程详情抽屉 |
| 通过 | 弹窗填写「审批意见」（可选），点「确认通过」 |
| 驳回 | 弹窗填写「审批意见」（**建议填写驳回理由**），点「确认驳回」 |
| 加签 | 提示「加签：在当前审批节点追加一个审批人（会签节点需其也通过）」；选择同租户启用用户后确认 |
| 转办 | 提示「转办：把该待办交给选定的用户处理，你将不再需要处理」；选择用户后确认 |

- 「我已处理」页签该位置显示处理意见（`-` 表示未填写）。

**审批语义（务必了解）**

- **或签**：任一审批人处理后该节点即完成，同节点其余待办自动变为「已失效」。
- **会签**：**所有**审批人都通过才推进；任一人驳回即节点驳回。
- 审批方式与超时提醒在**发起时快照**到任务上，之后修改流程定义**不影响**进行中的实例。
- 任一节点驳回 → 整个流程「已驳回」，其余待办失效；全部节点通过 → 「已通过」。
- 节点没有有效审批人（角色无成员 / 用户被停用或删除）时**自动通过**并记录「自动通过」。
- 超时未处理的待办会按节点配置给审批人发**站内信**催办（详情页以「催」标签体现）。

## 八、个人中心

入口：右上角头像 → 「个人中心」/「修改密码」（均为同一页面，非管理员也可访问）。

- **基本信息**（只读）：用户名、真实姓名、手机号、邮箱。如需修改请联系管理员在「用户管理」中调整。
- **修改密码**：旧密码、新密码、确认密码（两次必须一致）。新密码长度由「安全策略」的密码最小长度约束（默认 8 位）。
  提交成功后提示「密码修改成功，请重新登录」并自动退出——**所有设备上的旧登录状态同时失效**。

> 若账号没有任何菜单权限，登录后会直接落在本页并显示未分配菜单的告警条。

## 九、常见问题与注意事项

### 9.1 常见操作流程速查

| 目标 | 步骤 |
| --- | --- |
| 新建一个租户并让其管理员可用 | 租户管理新增租户 → 用户管理新增用户（选该租户、填初始密码、勾选「管理员」）→ 用「租户编码 + 用户名 + 密码」登录 |
| 让普通用户看到菜单 | 角色管理新增角色 → 分配菜单（勾选末级菜单）→ 分配权限（勾选接口权限点）→ 用户管理分配角色 → 用户重新登录 |
| 接入一个已有系统 | 应用管理注册（IFrame 或 API 代理）→ 应用实例为租户开通 → 菜单管理配置菜单（`appCode` 与注册一致）→ 需要底座代管接口权限时在权限管理登记该 `appCode` 的权限点 |
| 配置一个审批流程 | 流程角色新增角色并配置成员 → 流程定义新增流程 → 节点编排（选审批人类型/审批方式/超时提醒）→ 流程实例「发起流程」→ 审批人到「我的待办」处理 |
| 验证邮件/短信/企微配置 | 系统设置 → 邮件配置（发送测试邮件）/ 通知渠道（保存后渠道出现在消息发送下拉中） |
| 排查「谁在什么时候做了什么」 | 审计日志按用户名/模块/时间筛选；登录异常查登录日志 |

### 9.2 常见问题

| 现象 | 原因 / 处理 |
| --- | --- |
| 登录后没有菜单，只有个人中心 | 账号未被分配菜单：请管理员在「角色管理 → 分配菜单」中勾选菜单（并「分配权限」），或给用户勾选「管理员」 |
| 页面能打开但接口报「无权限访问该接口」 | 角色缺少对应接口权限点：在「角色管理 → 分配权限」中勾选；或该接口属于平台级资源，仅平台超管可用 |
| 看不到「系统设置 / 应用管理」的新增按钮 | 这些是平台级资源，仅平台超管（`tenantId = 0`）可写 |
| 修改密码后其它设备被登出 | 属安全机制：改密/重置密码会作废此前签发的所有 Token |
| 提示「请求过于频繁，请稍后再试」 | 触发了接口限流（登录 10 次/分钟、验证码与站点信息 30 次/分钟、初始化 5 次/分钟、续期与票据兑换 60 次/分钟），稍后重试 |
| 账号被锁定 | 连续登录失败达到「最大失败次数」；等待「锁定时长」或由超管调整安全策略 |
| 删除按钮点击后提示存在关联 | 删除保护：如租户下仍有用户/角色/实例、机构下有子机构或用户、菜单有子菜单、应用被开通等，需先处理下级数据 |
| 删除后重建「ID 变了、不能恢复数据」 | 系统统一使用**物理删除**，没有回收站；删除不可恢复 |
| 上传失败 | 检查扩展名是否在白名单内、文件是否超过 `server.max_upload_mb`（默认 50MB）；文件名异常（含 `../` 等）会被拒绝 |
| 消息发不出去 / 收不到 | 站内信在「收件箱」查看；邮件/短信/企微需先在「系统设置」配置对应渠道，且邮件与短信必须选择接收人（不支持广播） |
| 广播消息自己标记已读后别人还是未读 | 正常：广播消息的已读状态按人记录，互不影响 |
| 待办已通过，同节点的其它待办变成「已失效」 | 正常：该节点是「或签」，一人处理即视为完成 |
| 节点没配审批人却直接通过了 | 该节点解析不到有效审批人（角色无成员/用户停用），系统按「自动通过」处理并留下流转记录 |
| 无法保存流程节点 | 该流程存在审批中的实例，需等实例结束或撤销后再改 |
| 菜单点进去是空白页 / 404 | 菜单的「组件路径」或 iframe 地址配置有误；子应用 iframe 需在「组件路径」填写完整外部地址 |
| 审计日志里的参数是「[敏感参数已脱敏]」 | 正常：改密、重置密码、保存系统设置三类请求不记录原始请求体 |
| 导出 CSV 中文乱码 | 系统已输出 UTF-8 BOM，正常情况下 Excel 可直接打开；若仍乱码请用「数据 → 从文本/CSV」并选择 UTF-8 |

### 9.3 注意事项

- 首次上线后请立即修改 `admin` 的密码，并更换后端 `config.yaml` 中的数据库密码与 JWT 密钥。
- 删除操作不可逆（无回收站），重要数据操作前建议先备份数据库。
- 平台级资源（系统设置、应用定义、接口权限点）影响所有租户，修改前请评估影响面。
- 生产环境务必正确配置反向代理与可信代理地址，否则限流会误伤用户（属运维事项，见部署文档）。
- 普通用户的操作会记录操作日志（含请求参数），请勿在业务字段中填写密码等敏感信息。
